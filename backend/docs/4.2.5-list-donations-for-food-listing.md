# Prompt: Implement SRS 4.2.5 - List Donations for a Selected Food Listing

Implement a Donor endpoint that lists all donation/reservation records connected to one food listing. The output should help the Donor inspect who reserved or collected food, payment totals, status, and feedback.

## Flow

1. Donor calls `GET /api/donor/food-listings/:id/donations`.
2. Controller reads authenticated `donorProfileId` and listing id.
3. Service verifies the food listing belongs to the donor.
4. Reservation repository queries all reservations with `donationId`.
5. Repository populates or joins recipient account/profile data when available.
6. Service maps records into a Donor-facing DTO.
7. Controller returns paginated donation entries.

## Mechanism

Use the existing `Reservation` model as the donation record source because manual donations and online reservations are both stored there.

Each returned item should include:

- recipient username, or `manualRecipientName` for walk-in recipients.
- collected time from `collectedAt`.
- reserved time from `reservedAt`.
- quantity.
- status.
- total paid.
- payment method if available.
- feedback text or feedback entries connected to the reservation/listing.

The service should not expose private recipient profile fields that the Donor does not need.

## Algorithm

Ownership check:

```js
const listing = await Donation.findOne({ _id: donationId, donorProfileId });
if (!listing) throw new NotFoundError("Donation not found");
```

Paginated reservation query:

```js
const query = { donationId };
const [entries, total] = await Promise.all([
  Reservation.find(query)
    .sort({ reservedAt: -1, collectedAt: -1 })
    .skip(skip)
    .limit(limit)
    .populate("recipientProfileId"),
  Reservation.countDocuments(query),
]);
```

DTO mapping:

```js
return entries.map((reservation) => ({
  recipientUsername: reservation.recipientProfileId?.username ?? reservation.manualRecipientName,
  collectedAt: reservation.collectedAt,
  quantity: reservation.quantity,
  status: reservation.status,
  totalPaid: reservation.totalPaid,
  feedback: reservation.feedback,
}));
```

This design follows the milestone architecture by keeping business validation in services, database access in repositories, and response shaping in DTO mapping.
